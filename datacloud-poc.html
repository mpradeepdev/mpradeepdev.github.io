Project overview

What this POC shows

This proof of concept shows how healthcare-professional (HCP) data from several sources can be ingested, mapped, unified, enriched, segmented and activated inside Salesforce Data Cloud. HCP profile data from two Amazon S3 feeds and one import feed is combined with POA activity and representative (Employee) data, resolved into unified HCP profiles, and turned into audiences that can be delivered to a downstream destination.

Business objective and requirement
Objective: Build a relationship-aware HCP data foundation in Salesforce Data Cloud that brings together HCP profile feeds, connects POA activity and representative information, and makes the unified profile data useful for analytics and audience activation.

Bring together HCP profile data from multiple sources

What the POC delivered: Ingested three HCP feeds (two Amazon S3, one import) with source-record keys retained for traceability.

Connect POA activity and representative information

What the POC delivered: Modeled HCP–POA–Employee relationships through Account ID and representative ID.

Recognize the same HCP across sources

What the POC delivered: Configured Identity Resolution on name, email and phone using exact, normalized and fuzzy matching.

Make unified data useful for analytics and activation

What the POC delivered: Built Calculated Insights, segments with waterfall prioritization, and completed activation to Amazon S3.
How this POC was built
After approximately 2–3 months of self-learning, I built this POC to put my learning into practice and deepen my understanding of Salesforce Data Cloud, working through the full journey from raw source data to an activated audience in a Developer Edition org. It gave me hands-on, end-to-end practice with the core Data Cloud building blocks: data modeling, identity resolution, insight design, segmentation and activation.
DISCLAIMER This is a proof of concept, not a production deployment. It was built in a Developer Edition learning environment with dummy (synthetic) data and limited scale, so it does not reflect a real client implementation.
Key components

Key components, in simple language

Each stage of the POC builds on the one before it. Here is what each one does and what was done in this project.

1

Data Streams (S3 and import)

Connecting each source to Data Cloud so its data flows in. This is the entry point for everything that follows.

In this POC: Three HCP profile streams (two Amazon S3, one import) plus POA and Employee data streams were set up.
2

Data Lake Objects (DLOs)

The raw landing area. Each stream is stored as a DLO exactly as it arrived, so original data is preserved before any standardizing.

In this POC: HCP records landed as 346 + 352 + 330 = 1,028, alongside 1,017 POA and 47 Employee records. Source_Record_Id kept as the source key.
3

DMO mapping

Translating differently shaped source fields into one standard data model so everything speaks the same language.

In this POC: DLO fields were mapped into Data Model Objects (Individual / HCP, POA and Employee), with names, email, phone and dates standardized.
4

Relationships between DMOs

Defining how the objects connect, so activity can be traced to the right HCP and the right representative.

In this POC: HCP to POA through Account ID, and POA to Employee through representative ID.
5

Identity Resolution

Removing duplicates: recognizing when records from different sources describe the same HCP and merging them into one unified profile.

In this POC: Exact, normalized and fuzzy matching on name, email and phone. 1,028 source profiles became 800 unified profiles (22% consolidation).
6

Calculated Insights

Reusable business measures calculated on the unified, related data, ready for analysis and audience rules.

In this POC: Three insights were created and run: HCP Engagement Summary, POA Activity Summary and Representative Workload Summary.
7

Segmentation

Turning profile data and metrics into audiences, built in two ways.

In this POC: 1. Standard: High Value and High Spending segments, each on its own rule.
2. Waterfall: High Value is Priority 1, High Spending Priority 2, so each profile lands in one group.
8

Activation to Amazon S3

Sending the chosen audience out of Data Cloud so other systems can pick it up.

In this POC: Segment activation to the configured Amazon S3 target was completed, giving a file-based route for downstream processing.
